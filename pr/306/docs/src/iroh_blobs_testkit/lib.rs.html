1//! Protocol level conformance tests for [iroh-blobs] stores.
2//!
3//! An iroh-blobs store is anything that answers [`proto::Request`]s. This
4//! crate checks that a store answers them the way iroh-blobs clients expect.
5//! It only talks to the store through the protocol, either with the regular
6//! client API or with raw requests where the client would hide what the store
7//! does. So the same tests run against in-process and remote stores, and
8//! against stores written outside of iroh-blobs.
9//!
10//! # Usage
11//!
12//! The cases are a plain list, see [`cases`]. A [`Testkit`] runs them against
13//! fresh stores from a factory you provide.
14//!
15//! The easiest way to run them is a test target without the built-in test
16//! harness, which shows every case as a separate test:
17//!
18//! ```toml
19//! [[test]]
20//! name = "conformance"
21//! harness = false
22//! ```
23//!
24//! ```no_run
25//! // tests/conformance.rs
26//! use iroh_blobs::store::mem::MemStore;
27//! use iroh_blobs_testkit::{TestStore, Testkit};
28//!
29//! async fn mem_store() -> anyhow::Result<TestStore> {
30//!     Ok(TestStore::new(MemStore::new()))
31//! }
32//!
33//! fn main() {
34//!     Testkit::new(mem_store)
35//!         .skip("tags_model", "tags are not supported yet")
36//!         .main()
37//! }
38//! ```
39//!
40//! `cargo test --test conformance` then runs one test per case. The usual
41//! arguments work, e.g. `cargo test --test conformance export_` to filter,
42//! `-- --list` to list, or `-- --include-ignored` to also run skipped cases.
43//!
44//! Without a separate test target, run cases from a normal test:
45//!
46//! ```no_run
47//! # use iroh_blobs::store::mem::MemStore;
48//! # use iroh_blobs_testkit::{TestStore, Testkit};
49//! # async fn mem_store() -> anyhow::Result<TestStore> {
50//! #     Ok(TestStore::new(MemStore::new()))
51//! # }
52//! #[test]
53//! fn conformance() {
54//!     let testkit = Testkit::new(mem_store);
55//!     for case in iroh_blobs_testkit::cases() {
56//!         if let Err(cause) = testkit.run(case) {
57//!             panic!("{}: {cause:#}", case.name());
58//!         }
59//!     }
60//! }
61//! ```
62//!
63//! The factory is called once per generated input. Resources the store
64//! needs, such as a temp dir, can be tied to it with
65//! [`TestStore::with_guard`].
66//!
67//! # What is checked
68//!
69//! Most cases are properties: they run many times with generated blobs,
70//! ranges and operations, each time against a fresh store, and shrink to a
71//! minimal input on failure. Failure messages state the part of the contract
72//! that was violated. Expected values come from [bao-tree] and from simple
73//! models, never from another store implementation.
74//!
75//! The cases cover adding and exporting blobs, importing and exporting bao
76//! encoded data (complete, partial and incremental), observing bitfields,
77//! listing blobs, tags, and requests whose client goes away, as happens when
78//! a connection drops. Every run also checks that the store shuts down
79//! cleanly and that no request hangs.
80//!
81//! The tests assume a cooperative client, like the iroh-blobs clients: they
82//! look for ways to break a store through correct use of the protocol, not
83//! through malformed or adversarial request sequences. Persistence, crash and
84//! fault behavior are out of scope.
85//!
86//! [iroh-blobs]: https://docs.rs/iroh-blobs
87//! [bao-tree]: https://docs.rs/bao-tree
88//! [`proto::Request`]: iroh_blobs::api::proto::Request
