2//! The protocol that a store implementation needs to implement.
3//!
4//! A store needs to handle [`Request`]s. It is fine to just return an error for some
5//! commands. E.g. an immutable store can just return an error for import commands.
6//!
7//! Each command consists of a serializable request message and channels for updates
8//! and responses. The enum containing the full requests is [`Command`]. These are the
9//! commands you will have to handle in a store actor handler.
10//!
11//! This crate provides a file system based store implementation, [`crate::store::fs::FsStore`],
12//! as well as a mutable in-memory store and an immutable in-memory store.
13//!
14//! The file system store is quite complex and optimized, so to get started take a look at
15//! the much simpler memory store.
16//!
17//! # Listings
18//!
19//! [`Request::ListBlobs`], [`Request::ListTags`] and [`Request::ListTempTags`]
20//! end with an explicit `Done` or `Error`, since the client can not tell from
21//! the items when a listing is complete. See [`ListBlobsItem`].
22//!
23//! # The empty blob
24//!
25//! The empty blob, [`Hash::EMPTY`], is always present. The client in [`crate::api`]
26//! answers requests that read its bytes or delete it without asking the store, so a
27//! store never gets such a request, and [`Request::ListBlobs`] must not list it.
28//! Like everything else about this protocol, this is not enforced: a store may rely on
29//! it, but a client that sends such a request anyway gets unspecified results.
30//!
31//! File export is the exception: [`Request::ExportPath`] must reach the store even
32//! for the empty blob, because the target path is on the store's filesystem. The
33//! store creates the empty file without creating a blob entry.
34//!
35//! An import only learns that its data is empty once it is hashed. At that point a
36//! store does nothing but answer with a [`TempTag`] that is not tracked, since the
37//! empty blob never needs protection. It does not create an entry for it.

187/// Enter an exclusive GC session.
188///
189/// The first event is a [`GcEvent::Snapshot`], sent once HashSeq roots are
190/// frozen and tag mutations are suspended. The client then sends sweep deletes
191/// as [`GcRunUpdate::Delete`], and gets a [`GcEvent::Deleted`] for each, in
192/// order. Closing the update channel exits the session, also on cancellation;
193/// the store finishes the deletes it received before it releases the session.
194/// Reads and ordinary blob writes remain available. A client must not await,
195/// while holding the session, anything the session holds back: tag mutations,
196/// import completions, and writes to or deletes of frozen roots. That would
197/// deadlock, since those wait for the session to end.
198#[derive(Debug, Serialize, Deserialize)]
199pub struct GcRunRequest;

207impl GcSnapshot {
208    pub(crate) fn hashseqs(&self) -> std::collections::HashSet<Hash> {
209        self.roots
210            .iter()
211            .filter(|root| !root.format.is_raw())
212            .map(|root| root.hash)
213            .collect()
214    }
215}

302/// Export the given ranges in bao format, with the iroh block size.
303///
304/// The returned stream should be verified by the store.
305///
306/// The response starts with the [`EncodedItem::Size`] of the blob, followed by
307/// [`EncodedItem::Parent`] and [`EncodedItem::Leaf`] items for the requested
308/// ranges in pre-order, so leaves come in ascending order and end at the size
309/// at the latest. A range past the end of the blob stands for the last chunk.
310/// The stream is complete with the leaf that reaches the end of the requested
311/// ranges or the size, whichever comes first, or right after the size if there
312/// is nothing to send. A stream that ends before that was cut short. An
313/// [`EncodedItem::Error`] can come at any time, and is the last item.
314/// [`EncodedItem::Done`] is not needed, but counts as the last item too.
315///
316#[doc = include_str!("../../docs/img/export_bao.svg")]
317#[derive(Debug, Serialize, Deserialize)]
318pub struct ExportBaoRequest {
319    pub hash: Hash,
320    pub ranges: ChunkRanges,
321}

458/// An item of a [`Request::ListBlobs`] listing.
459///
460/// A listing is zero or more [`Self::Hash`] items, followed by [`Self::Done`]
461/// on success or [`Self::Error`] on failure. An empty listing still sends
462/// [`Self::Done`]. Dropping the sender does not complete a listing: a store
463/// task that panics or is aborted drops its sender, and the client can not
464/// tell from the items that some are missing. So a client reports a listing

466/// item without waiting for the close.

548pub(crate) fn tags_from_range<R, E>(range: R) -> (Option<Tag>, Option<Tag>)
549where
550    R: RangeBounds<E>,
551    E: AsRef<[u8]>,
552{
553    let from = match range.start_bound() {
554        Bound::Included(start) => Some(Tag::from(start.as_ref())),
555        Bound::Excluded(start) => Some(Tag::from(start.as_ref()).successor()),
556        Bound::Unbounded => None,
557    };
558    let to = match range.end_bound() {
559        Bound::Included(end) => Some(Tag::from(end.as_ref()).successor()),
560        Bound::Excluded(end) => Some(Tag::from(end.as_ref())),
561        Bound::Unbounded => None,
562    };
563    (from, to)
564}

639/// Progress events for importing from any local source.
640///
641/// An import first copies the data. The [`Self::Size`] comes once, before the
642/// copy for sources of known size such as blobs and files, and after it for
643/// streams. [`Self::CopyDone`] follows if the data was copied, which an import
644/// that references a file where it is does not do. Then the outboard is
645/// computed, and finally [`Self::Done`] comes. Only the size and the final
646/// [`Self::Done`] or [`Self::Error`] are guaranteed; [`Self::CopyProgress`] and
647/// [`Self::OutboardProgress`] are best effort and may not come at all. Progress
648/// never goes backwards or past the size. An [`Self::Error`] can come at any
649/// time, and is the last event.
650///
651#[doc = include_str!("../../docs/img/add_progress.svg")]
652#[derive(Debug, Serialize, Deserialize)]
653pub enum AddProgressItem {
654    /// Progress copying the file into the data directory.
655    ///
656    /// On most modern systems, copying will be done with copy on write,
657    /// so copying will be instantaneous and you won't get any of these.
658    ///
659    /// The number is the *byte offset* of the copy process.
660    ///
661    /// This is an ephemeral progress event, so you can't rely on getting
662    /// regular updates.
663    CopyProgress(u64),
664    /// Size of the file or stream has been determined.
665    ///
666    /// For some input such as blobs or files, the size is immediately known.
667    /// For other inputs such as streams, the size is determined by reading
668    /// the stream to the end.
669    ///
670    /// This is a guaranteed progress event, so you can rely on getting exactly
671    /// one of these.
672    Size(u64),
673    /// The copy part of the import operation is done.
674    ///
675    /// This is only sent if the import copied the data, and then exactly once.
676    /// An import that references a file where it is, see
677    /// [`ImportMode::TryReference`], does not copy it and does not send this.
678    CopyDone,
679    /// Progress computing the outboard and root hash of the imported data.
680    ///
681    /// This is an ephemeral progress event, so you can't rely on getting
682    /// regular updates.
683    OutboardProgress(u64),
684    /// The import is done. Once you get this event the data is available
685    /// and protected in the store via the temp tag.
686    ///
687    /// This is a guaranteed progress event, so you can rely on getting exactly
688    /// one of these if the operation was successful.
689    ///
690    /// This is one of the two possible final events. After this event, there
691    /// won't be any more progress events.
692    Done(TempTag),
693    /// The import failed with an error. Partial data will be deleted.
694    ///
695    /// This is a guaranteed progress event, so you can rely on getting exactly
696    /// one of these if the operation was unsuccessful.
697    ///
698    /// This is one of the two possible final events. After this event, there
699    /// won't be any more progress events.
700    Error(#[serde(with = "crate::util::serde::io_error_serde")] io::Error),
701}
702
703impl From<io::Error> for AddProgressItem {
704    fn from(e: io::Error) -> Self {
705        Self::Error(e)
706    }
707}

734/// Progress events for exporting to a local file.
735///
736/// Exporting does not involve outboard computation, so the events are simpler
737/// than [`AddProgressItem`]. The [`Self::Size`] comes first, then the data is
738/// copied, and finally [`Self::Done`] comes. Only the size and the final
739/// [`Self::Done`] or [`Self::Error`] are guaranteed; [`Self::CopyProgress`] is
740/// best effort and may not come at all. Progress never goes backwards or past
741/// the size. An [`Self::Error`] can come at any time, and is the last event.
742///
743#[doc = include_str!("../../docs/img/export_progress.svg")]
744#[derive(Debug, Serialize, Deserialize)]
745pub enum ExportProgressItem {
746    /// The size of the file being exported.
747    ///
748    /// This is a guaranteed progress event, so you can rely on getting exactly
749    /// one of these.
750    Size(u64),
751    /// Progress copying the file to the target directory.
752    ///
753    /// On many modern systems, copying will be done with copy on write,
754    /// so copying will be instantaneous and you won't get any of these.
755    ///
756    /// This is an ephemeral progress event, so you can't rely on getting
757    /// regular updates.
758    CopyProgress(u64),
759    /// The export is done. Once you get this event the data is available.
760    ///
761    /// This is a guaranteed progress event, so you can rely on getting exactly
762    /// one of these if the operation was successful.
763    ///
764    /// This is one of the two possible final events. After this event, there
765    /// won't be any more progress events.
766    Done,
767    /// The export failed with an error.
768    ///
769    /// This is a guaranteed progress event, so you can rely on getting exactly
770    /// one of these if the operation was unsuccessful.
771    ///
772    /// This is one of the two possible final events. After this event, there
773    /// won't be any more progress events.
774    Error(super::Error),
775}
776
777impl From<super::Error> for ExportProgressItem {
778    fn from(e: super::Error) -> Self {
779        Self::Error(e)
780    }
781}

783/// The import mode describes how files will be imported.
784///
785/// This is a hint to the import trait method. For some implementations, this
786/// does not make any sense. E.g. an in memory implementation will always have
787/// to copy the file into memory. Also, a disk based implementation might choose
788/// to copy small files even if the mode is `Reference`.
789#[derive(Debug, Clone, Copy, PartialEq, Eq, Default, Serialize, Deserialize)]
790pub enum ImportMode {
791    /// This mode will copy the file into the database before hashing.
792    ///
793    /// This is the safe default because the file can not be accidentally modified
794    /// after it has been imported.
795    #[default]
796    Copy,
797    /// This mode will try to reference the file in place and assume it is unchanged after import.
798    ///
799    /// This has a large performance and storage benefit, but it is less safe since
800    /// the file might be modified after it has been imported.
801    ///
802    /// Stores are allowed to ignore this mode and always copy the file, e.g.
803    /// if the file is very small or if the store does not support referencing files.
804    TryReference,
805}
